## Additional Notes

This section was added later (2025-11-11) to provide detailed migration guides and examples.

### Added

- Introduced `DonutRendererInterface` for dependency injection (#124)
  - Enables interface-based dependency injection for `DonutRenderer`
  - Improves testability by allowing mock implementations
  - Follows dependency inversion principle for better architecture

  **Example**:
  ```php
  // In your module or test setup, you can now inject through interface
  class CustomDonutModule extends AbstractModule
  {
      protected function configure(): void
      {
          $this->bind(DonutRendererInterface::class)->to(CustomDonutRenderer::class);
      }
  }

  // The interface provides these methods:
  interface DonutRendererInterface
  {
      public function setView(string $uri, string $view): void;
      public function render(string $template): string;
  }
  ```

### Changed

- Updated dependency injection bindings to use `DonutRendererInterface` (#124)
  - `DonutRepository`, `DonutRequest`, and `ResourceDonut` now depend on the interface
  - Module bindings updated in `DonutCacheModule` and `QueryRepositoryModule`
  - **Note**: This is a non-breaking change. The default concrete implementation (`DonutRenderer`) remains unchanged and is bound to the interface automatically

  **Migration**: No action required. Existing code continues to work without modifications. If you want to provide a custom renderer, implement `DonutRendererInterface`:

  ```php
  class MyCustomRenderer implements DonutRendererInterface
  {
      public function setView(string $uri, string $view): void
      {
          // Your custom implementation
      }

      public function render(string $template): string
      {
          // Your custom rendering logic
      }
  }
  ```
